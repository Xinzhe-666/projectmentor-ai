# ProjectMentor AI Roadmap

## V4.0 当前可试用版本

当前版本已经打通项目审计和面试准备的主流程，适合本地演示、Docker Compose 演示和 Cloudflare Tunnel 临时试用。

已完成：

- Spring Boot 3 后端基础工程。
- Vue 3 前端基础页面。
- 用户注册、登录、JWT 鉴权和 BCrypt 密码加密。
- 项目创建、列表、详情和删除。
- README 粘贴保存。
- 普通项目 ZIP 上传、多文件解析和安全过滤，当前最大支持 200MB。
- README 风险规则扫描。
- 证据链展示。
- 项目审计报告生成。
- OpenAI-compatible AI 审计增强接口。
- AI 不可用时降级为规则版报告。
- AI 幻觉检测。
- 规则版模拟面试 V1。
- 额度账户、额度流水、报告消耗额度和失败返还。
- 异步分析任务和 Redis 进度缓存。
- Docker Compose + Nginx 部署。
- Cloudflare Tunnel 临时试用说明。
- README 和演示文档整理。

当前限制：

- 规则库仍然比较基础，需要继续覆盖更多项目类型和夸大表达。
- 面试深挖当前仍是规则版 V1，追问逻辑和问题库还需要继续扩展。
- AI 增强依赖外部 OpenAI-compatible API，未配置 Key 时只输出规则版报告。
- 当前只有额度账户和流水，没有接入真实支付。
- 仍需要真实用户测试来调整规则、文案和演示流程。

## V4.1 PDF 导出 / 分享报告（基本完成）

已完成：

- 报告详情页支持通过浏览器打印窗口另存为 PDF。
- 面试复盘支持通过浏览器打印窗口另存为 PDF。
- 审计报告支持随机 token 只读分享链接。
- 报告页和公开分享页完成视觉打磨，让风险点、证据链和建议更适合面试前复盘使用。
- V4.1-10 完成首页体验收口：首页补充产品定位、适合人群、核心流程、试用能力和试用版边界。
- V4.1-10 增加试用提示：首页与 Dashboard 均提醒不要上传真实商业机密、真实密钥或公司内部代码，AI 结论仅供学习、项目复盘和面试准备参考。
- V4.1-10 增加“请作者喝咖啡”入口：仅展示 `/donate/wechat.png` 和 `/donate/alipay.png` 本地二维码路径，自愿支持，不影响功能使用，不是支付系统。
- V4.1-10 增加轻量反馈入口：复制反馈模板并跳转 GitHub Issues，不新增数据库表，不做正式工单系统。
- V4.1-10 明确真实收款码图片不提交到 GitHub，本地部署时可放在 `frontend/projectmentor-web/public/donate/`。
- V4.1-9 完成上线安全收口：MySQL 和 Redis 不映射公网端口，生产环境只开放 `22`、`80`、`443`，`.env` 和真实密钥不提交，`AI_API_KEY`、`JWT_SECRET`、`MYSQL_ROOT_PASSWORD` 均通过环境变量配置。
- V4.1-9 固化轻量部署流程：2 核 2G 服务器可以运行项目，但不建议在服务器执行 `docker compose build frontend`、`docker compose up -d --build` 或 `npm run build`；前端更新走本地 `npm.cmd run build`、压缩 `dist.zip`、上传服务器、清空旧静态文件、`docker cp` 覆盖、重启 `frontend` 和 `nginx`。
- 后端 Java 代码更新时，低配服务器可执行 `docker compose build backend` 和 `docker compose up -d backend`，如服务器卡顿，后续升级为 GitHub Actions 构建镜像。

## V4.2 项目问答

V4.2-1 已完成：

- 项目详情页新增“项目问答”区域，用户可以对当前项目提问。
- 后端基于已保存 README 和 ZIP 解析文本做轻量关键词检索、路径/内容打分和证据片段抽取。
- 回答返回文件路径、命中原因和证据片段；AI 可用时再基于证据组织回答。
- AI 不可用时返回规则检索结果，不直接编造答案。
- 项目问答复用 `UserContext` 和项目归属校验，只允许用户查询自己的项目文件。
- 新增 `pm_project_qa_record` 保存问答记录。

V4.2-2 已完成：

- 新增 `GET /api/projects/{projectId}/qa/history`，默认返回最近 20 条问答记录，按 `create_time` 倒序。
- 新增 `DELETE /api/projects/{projectId}/qa/history/{recordId}`，使用 `deleted = 1` 逻辑删除。
- 历史查询和删除都按当前登录用户校验项目归属，并按 `userId + projectId` 隔离数据。
- 项目详情页展示问答历史，提问成功后自动刷新历史并清空输入框。
- 建议追问和快捷问题都填入输入框，不自动触发新的 AI 调用。
- 每条回答支持复制，复制内容包含问题、回答、证据文件路径和建议追问。
- 证据片段默认折叠，可展开或收起。
- AI 不可用时显示规则检索结果提示；无证据时提示补充 README、项目 ZIP 或更具体的问题。

V4.2-3 已完成：

- 项目问答响应新增 `evidenceLevel`、`evidenceLevelText`、`evidenceSummary`、`confidenceScore`、`interviewAnswer` 和 `resumeRisk`。
- 证据可信度由后端规则根据检索证据计算，不由 AI 自行判断。
- `confidenceScore` 表示当前上传文件的证据充分度，不是 AI 正确率。
- AI 可用时继续强约束只能基于证据回答，并必须输出直接回答、证据依据、面试讲法、简历风险提示和可能追问。
- AI 不可用时仍返回规则检索结果，同时由规则生成证据等级、面试讲法和简历风险提示。
- 前端展示证据可信度卡片、面试讲法、简历风险提示，并支持复制面试版回答。
- 历史记录展示证据等级和可信度分数；旧记录不需要新增数据库字段，会根据已保存证据动态计算。

V4.2-4 已完成：

- 增强项目问答关键词提取，支持中文问题、英文技术词、camelCase、snake_case、kebab-case、大小写归一化和无意义短词过滤。
- 增加轻量技术同义词映射，覆盖登录鉴权、用户、Redis / 缓存、数据库、上传、报告、AI、异步、部署和额度等方向。
- 优化文件路径和文件角色权重，提高 Controller、Service、Config、Interceptor、Filter、Util、Mapper、Entity、DTO / VO、配置、部署和 SQL 文件的证据优先级。
- 降低锁文件、构建产物、压缩产物、大型样式文件、自动生成文件和日志类文件的误命中影响。
- 优化证据 snippet 截取，优先返回关键词、类名、方法名或配置块附近片段，并控制长度。
- 增强 `evidence.reason`，解释文件路径、内容关键词、技术词和文件角色为什么相关。
- 前端证据卡片强化命中原因展示，支持复制证据文件路径，并在证据较弱时提示补充 README、上传更多代码文件或把问题问得更具体。

边界说明：

- 当前不是成熟向量 RAG，不接入 Milvus，不做 embedding，不引入向量数据库。
- 当前适合回答“这个功能在哪里实现”“哪些文件可以作为面试证据”等问题。
- 后续 V4.2-5 或 V4.3 可以在反馈足够后评估向量检索升级或管理员后台。

## V4.3 管理员后台 / 用户反馈

V4.3-1 已完成：

- 新增管理员后台只读 MVP，用于查看试用版运行数据，不做复杂 RBAC。
- 管理员通过 `ADMIN_EMAILS` 环境变量配置，支持英文逗号分隔、去空格和忽略大小写。
- 新增 `/api/admin/me`、`/api/admin/stats`、最近用户、最近项目、最近报告和最近问答接口。
- `/api/admin/**` 数据接口在后端校验管理员权限，普通用户不能访问后台数据。
- 前端新增 `/admin` 页面，展示统计卡片和最近记录表格；非管理员访问显示无权限提示。
- 后台不返回密码、AI Key、JWT 密钥、数据库密码、完整项目源码或完整问答证据 JSON。
- 该阶段后台只读，不提供删除用户、封号、额度调整或导出敏感数据能力。

V4.3-2 已完成：

- 新增管理员额度管理，用于搜索用户、查看余额和最近额度流水。
- 支持管理员为指定用户增加额度，接口为 `/api/admin/credits/grant`。
- 发放额度必须填写正整数额度和发放原因，并限制单次额度上限。
- 每次发放都会在同一事务中更新余额并写入额度流水，流水类型为 `ADMIN_GRANT`。
- 流水备注包含发放原因、adminId 和 adminEmail，便于后续审计。
- 当前不是支付系统，不做扣减额度、批量发放、支付回调、删除用户或封禁用户。

V4.3-3 已完成：

- 新增站内反馈提交接口 `POST /api/feedback`，要求登录后提交，自动记录当前用户和来源页面。
- 新增 `pm_feedback` 表，保存反馈类型、内容、联系方式、状态、管理员备注和时间字段。
- 管理员反馈接口位于 `/api/admin/feedback/**`，支持列表筛选、详情查看和状态更新。
- 管理员可按类型、状态和关键词筛选反馈，关键词覆盖反馈内容、联系方式和用户邮箱。
- 前端反馈弹窗从轻量复制模板升级为站内提交，保留复制模板和 GitHub Issues 作为备用入口。
- `/admin` 页面新增“反馈管理”区域，可查看反馈详情并更新状态为待处理、处理中、已解决或暂不处理。
- 当前不是复杂工单系统，不做邮件通知、客服聊天、反馈删除、用户删除、封号、扣减额度或数据导出。
- 已有线上数据库需要手动执行 `pm_feedback` 建表 SQL；全新部署会随 `init.sql` 初始化。

计划目标：

- 在只读看板基础上继续观察真实试用数据，必要时再补充更安全的管理能力。
- 继续观察反馈中的高频问题，收集风险识别是否准确、报告建议是否有用。
- 基于反馈优化规则库、文案和面试追问。
- 让当前额度系统和反馈入口保持克制边界，避免过早做复杂后台。

## V4.4 更正式的部署和用户体系

计划目标：

- 整理更正式的服务器部署说明。
- 补充域名、HTTPS、日志和基础运维说明。

- 梳理更清晰的试用流程和用户数据边界。

## 暂不承诺

以下能力当前不作为已完成能力描述：

- 成熟商业部署。
- 性能压测结论。
- 真实支付系统。
- 完整企业级权限系统。
- 完全自动化、完全准确的 AI 项目审计。
