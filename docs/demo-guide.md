# ProjectMentor AI 演示指南

这份指南面向用户或面试官，用于快速走通 ProjectMentor AI 的核心演示流程。

## 1. 启动项目

Docker Compose 方式：

```bash
cp .env.example .env
docker compose up -d --build
```

启动后访问：

```text
http://localhost
```

本地开发方式：

- 后端：进入 `backend/projectmentor-server`，执行 `mvn spring-boot:run`。
- 前端：进入 `frontend/projectmentor-web`，执行 `npm install` 和 `npm run dev`。

## 2. 注册登录

1. 打开前端页面。
2. 注册一个新账号。
3. 登录后进入主界面。
4. 新用户默认获得 3 次分析额度。

演示重点：

- 用户密码使用 BCrypt 保存。
- 登录成功后由 JWT 维护访问身份。
- 后续项目、文件、报告、任务、面试和额度都按当前用户隔离。

## 3. 创建项目

1. 进入项目页面。
2. 点击创建项目。
3. 填写项目名称、项目描述、技术栈和项目类型。
4. 保存后进入项目详情页。

建议演示项目：

- 一个 Spring Boot 后端项目。
- 或一个包含 README、`pom.xml`、`application.yml`、SQL 和 Java 代码的全栈 MVP。

## 4. 上传 ZIP

1. 在项目详情页选择上传 ZIP。
2. 上传项目压缩包。
3. 查看解析结果，包括保存文件数、跳过文件数和警告信息。

演示重点：

- ZIP 限制 10MB。
- 系统只解析白名单文本文件。
- 会跳过 `.git`、`target`、`node_modules`、`dist` 等目录。
- 会过滤危险路径和二进制文件。

## 5. 规则扫描

1. 点击规则扫描。
2. 查看扫描结果中的风险点。
3. 查看系统识别到的证据。

演示重点：

- 系统不会直接相信 README。
- README 中提到的技术能力需要有文件、配置或代码证据。
- 规则扫描是稳定输出，AI 增强只是补充。

## 6. 生成报告

1. 点击生成报告或启动异步分析。
2. 如果使用异步分析，观察任务进度条变化。
3. 等待任务完成后进入报告详情。

演示重点：

- 生成报告会消耗 1 次额度。
- 任务进度会写入 Redis，同时 MySQL 保留任务状态。
- AI Key 未配置时，系统仍会生成规则版报告。

## 7. 查看证据链

1. 打开报告详情。
2. 查看总分和各维度评分。
3. 查看风险点列表。
4. 查看证据链区域。
5. 查看简历写法建议。

演示重点：

- 报告不是只给结论，还会展示依据。
- 证据链可以帮助用户判断哪些内容能写进简历，哪些需要降级表达。

## 8. AI 幻觉检测

1. 进入 AI 幻觉检测页面。
2. 选择项目，或直接粘贴 AI 对项目的评价。
3. 点击检测。
4. 查看可信度、客观性、风险点和更稳妥的改写建议。

可以粘贴的测试内容：

```text
这个项目非常完整，可以直接写进简历，面试基本没有问题。它体现了复杂系统设计能力，也可以包装成大型业务平台。
```

演示重点：

- 系统会识别过度鼓励和缺少证据的表达。
- 检测结果会提醒用户避免把不确定内容直接写入简历。

## 9. 模拟面试

1. 进入模拟面试页面。
2. 选择项目和面试模式。
3. 启动面试。
4. 回答第一轮问题。
5. 查看系统追问、评分和反馈。
6. 结束面试并查看总结。

演示重点：

- 当前是规则版 V1。
- 更适合展示面试深挖思路，而不是把它包装成完整智能面试系统。
- 追问重点围绕项目真实性、技术细节和用户是否理解代码。

## 10. 查看额度

1. 进入额度页面。
2. 查看剩余额度。
3. 查看额度流水。

演示重点：

- 注册赠送额度。
- 报告生成消耗额度。
- 失败时返还额度。
- 当前没有接入支付，只是额度系统原型。
