# ProjectMentor AI 演示指南

这份指南面向用户或面试官，用于快速走通 ProjectMentor AI 的核心演示流程。

## 最终演示路线

1. 打开首页，查看产品定位、适合人群、核心流程、当前试用能力和试用版边界。
2. 点击“反馈建议”，确认可以复制反馈模板并跳转 GitHub Issues。
3. 点击“请作者喝咖啡”，确认只展示自愿支持二维码弹窗，不影响任何功能使用。
4. 注册 / 登录。
5. 创建项目，填写项目名称、项目描述、技术栈和项目类型。
6. 上传普通 ZIP，确认系统解析核心文本文件并过滤无关目录。
7. 在项目详情页使用“项目问答”，提问“JWT 在哪里实现？”或“这个项目用了 Redis 吗？”，并查看历史、证据可信度、命中原因、面试讲法、简历风险、建议追问、复制回答和复制文件路径能力。
8. 执行规则扫描，查看 README 风险点和证据链。
9. 生成 AI 报告；AI Key 未配置时会自动 fallback 为规则版报告。
10. 在报告详情页查看总分、维度评分、风险点、证据链、建议和简历三版描述。
11. 点击“打印 / 浏览器另存为 PDF”，在浏览器打印窗口的目标打印机中选择“另存为 PDF”保存审计报告。
12. 生成只读分享链接，复制后用无痕窗口打开，确认公开页不需要登录且不展示敏感信息。
13. 进入 AI 幻觉检测，粘贴一段过度夸大的项目评价并查看风险提示。
14. 启动模拟面试，回答追问并查看评分、反馈和总结。
15. 点击“打印 / 浏览器另存为 PDF”，在浏览器打印窗口的目标打印机中选择“另存为 PDF”保存面试复盘。
16. 如果当前账号邮箱已配置在 `ADMIN_EMAILS` 中，进入“管理员后台”，查看只读统计卡片和最近记录。

## 演示注意事项

- 本地演示需要 MySQL、Redis、后端和前端都已运行；Docker Compose 可一次性启动这些服务，本地开发方式需要分别启动。
- AI Key 未配置或调用失败时，系统会 fallback 到规则版报告，不应把演示包装成完整 AI 审计能力。
- 项目问答当前是轻量检索增强问答 MVP，不是成熟向量 RAG，不使用 Milvus、embedding 或向量数据库；AI 不可用时只展示检索证据，不编造答案。
- 项目问答里的 `confidenceScore` 是证据充分度，不是 AI 正确率；证据不足时不建议写进简历或过度包装。
- V4.2-4 优化了关键词扩展、技术同义词、文件类型权重、证据 snippet 和命中原因，但仍属于轻量检索增强，不应包装成完整语义检索能力。
- 问答历史仅当前登录用户可见，历史删除也会按用户和项目校验。
- 管理员后台当前是只读 MVP，通过 `ADMIN_EMAILS` 配置管理员邮箱；普通用户不会看到侧边栏入口，手动访问也只显示无权限提示。
- 管理员后台只展示统计和最近记录，不展示密码、密钥、AI Key、数据库密码、完整项目源码或问答证据 JSON。
- Cloudflare Tunnel 只适合临时试用和短时间演示，生成的是临时链接，不适合作为正式部署方式。
- 公开分享页只展示脱敏后的只读报告内容，不展示 userId、邮箱、源码内容、AI 调用日志或额度流水。
- 审计报告分享链接是只读链接，后端使用随机 token 访问公开报告，用户可以在报告详情页关闭分享。
- 首页和 Dashboard 已提示试用边界：不要上传真实商业机密、真实密钥或公司内部代码，AI 结论仅供学习、项目复盘和面试准备参考。
- “请作者喝咖啡”只是自愿支持二维码弹窗，不接入支付接口，不影响功能使用；真实二维码文件只放在本地部署目录，不提交到 GitHub。
- 反馈入口当前是轻量版，只提供模板复制和 GitHub Issues 跳转，不是正式工单系统。
- 2 核 2G 轻量服务器可以运行演示环境，但不适合每次在服务器构建前端；不要在服务器执行 `docker compose build frontend`、`docker compose up -d --build` 或 `npm run build`，前端更新走本地构建后上传覆盖。

## 1. 启动项目

Docker Compose 方式：

```bash
cp .env.example .env
docker compose up -d --build
```

该命令适合本地或资源充足环境的完整 Compose 演示。低配服务器日常更新请使用下方前端轻量更新流程。

启动后访问：

```text
http://localhost
```

Cloudflare Tunnel 临时试用方式：

- 如果只是想把本机运行的项目临时发给同学试用，可以先启动本地后端和前端，再用 Cloudflare Tunnel 暴露前端开发服务。
- 该方式会生成一个 `https://*.trycloudflare.com` 临时链接，适合短时间演示，不适合长期正式运营。
- 详细步骤见 [cloudflare-tunnel-demo.md](cloudflare-tunnel-demo.md)。

本地开发方式：

- 后端：进入 `backend/projectmentor-server`，执行 `mvn spring-boot:run`。
- 前端：进入 `frontend/projectmentor-web`，执行 `npm install` 和 `npm run dev`。

服务器试用环境前端轻量更新：

本地 Windows PowerShell：

```powershell
cd C:\Users\LiXin\Desktop\projectmentor-ai\frontend\projectmentor-web
npm.cmd run build
Remove-Item -Force dist.zip -ErrorAction SilentlyContinue
Compress-Archive -Path dist* -DestinationPath dist.zip -Force
scp dist.zip root@服务器IP:/opt/projectmentor-ai/frontend-dist.zip
```

服务器：

```bash
cd /opt/projectmentor-ai
rm -rf /tmp/projectmentor-frontend-dist
mkdir -p /tmp/projectmentor-frontend-dist
unzip -o frontend-dist.zip -d /tmp/projectmentor-frontend-dist
docker exec projectmentor-frontend-assets sh -c "rm -rf /usr/share/nginx/html/*"
docker cp /tmp/projectmentor-frontend-dist/. projectmentor-frontend-assets:/usr/share/nginx/html/
docker compose restart frontend nginx
docker compose ps
```

后端如果修改 Java 代码，低配服务器可以执行以下命令，但可能较慢：

```bash
docker compose build backend
docker compose up -d backend
```

如服务器卡顿，后续可升级为 GitHub Actions 构建镜像。

公网试用安全边界：

- MySQL 和 Redis 不映射公网端口，只允许后端在 Docker Compose 内部网络中通过 `mysql`、`redis` 服务名访问。
- 生产环境只开放 `22`、`80`、`443`；云防火墙不应开放 `3306`、`6379`。
- `.env` 不提交；`AI_API_KEY`、`JWT_SECRET`、`MYSQL_ROOT_PASSWORD` 必须通过环境变量配置。
- 本地部署如需展示自愿支持二维码，可在 `frontend/projectmentor-web/public/donate/` 下放置 `wechat.png` 和 `alipay.png`；真实图片不要提交到 GitHub。

## 2. 注册登录

1. 打开前端页面。
2. 注册一个新账号。
3. 登录后进入主界面。
4. 新用户默认获得 3 次分析额度。

演示重点：

- 用户密码使用 BCrypt 保存。
- 登录成功后由 JWT 维护访问身份。
- 后续项目、文件、报告、任务、面试和额度都按当前用户隔离。

## 3. 创建项目

1. 进入项目页面。
2. 点击创建项目。
3. 填写项目名称、项目描述、技术栈和项目类型。
4. 保存后进入项目详情页。

建议演示项目：

- 一个 Spring Boot 后端项目。
- 或一个包含 README、`pom.xml`、`application.yml`、SQL 和 Java 代码的全栈 MVP。

## 4. 上传 ZIP

1. 在项目详情页选择上传 ZIP。
2. 直接上传从 GitHub、IDEA 或项目文件夹压缩出来的普通项目 ZIP。
3. 查看解析结果，包括保存文件数、跳过文件数、跳过原因和警告信息。

演示重点：

- ZIP 上传当前支持普通项目 ZIP，最大 200MB。
- 系统会自动过滤 `.git`、`target`、`node_modules`、`dist`、`build` 等目录。
- 大文件上传可能需要数分钟，请不要刷新页面；删除 `node_modules`、`target`、`.git` 后再压缩可显著提升速度。
- 系统只解析核心文本文件，不保存二进制文件。
- 会过滤危险路径，并限制单文件大小、保存文本总量和 ZIP entry 数。

## 5. 项目问答

1. 在项目详情页找到“项目问答”区域。
2. 点击快捷问题，或输入类似“JWT 在哪里实现？”的问题。
3. 点击“提问”，查看回答、AI 是否参与、证据可信度、文件路径、命中原因和证据片段。
4. 点击建议追问，确认只填入输入框，不会自动触发新的 AI 调用。
5. 查看“面试讲法”和“简历风险提示”，确认表述是克制、可复盘的。
6. 展开或收起较长证据片段，确认页面不会被长 snippet 撑开。
7. 点击“复制回答”“复制面试版回答”和“复制文件路径”，确认复制内容和文件路径都能正常写入剪贴板。
8. 刷新历史，确认最近问答按时间倒序展示，并能展开查看完整回答；如需演示删除，可删除自己的某条记录。

演示重点：

- 当前是基于已上传文件的轻量检索增强问答 MVP，不是成熟向量 RAG，不接入 Milvus、embedding 或向量数据库。
- 检索只使用当前项目保存的 README 和 ZIP 解析文本。
- V4.2-4 会把中文问题扩展到常见英文技术词，并结合文件路径、内容命中、技术词、文件角色和配置文件做综合打分。
- 证据片段优先截取关键词、类名、方法名或配置块附近内容；命中原因会解释为什么这些文件被选为证据。
- 回答必须附带证据；证据不足时会明确提示。
- AI Key 未配置或调用失败时，系统会返回规则检索到的证据片段，不直接编造答案。
- 证据可信度分为强证据、中等证据、弱证据和证据不足；分数只表示当前上传文件的证据充分度。
- 问答历史默认展示最近 20 条，并按当前登录用户和项目隔离。

## 6. 规则扫描

1. 点击规则扫描。
2. 查看扫描结果中的风险点。
3. 查看系统识别到的证据。

演示重点：

- 系统不会直接相信 README。
- README 中提到的技术能力需要有文件、配置或代码证据。
- 规则扫描是稳定输出，AI 增强只是补充。

## 7. 生成报告

1. 点击生成报告或启动异步分析。
2. 如果使用异步分析，观察任务进度条变化。
3. 等待任务完成后进入报告详情。

演示重点：

- 生成报告会消耗 1 次额度。
- 任务进度会写入 Redis，同时 MySQL 保留任务状态。
- AI Key 未配置时，系统仍会生成规则版报告。

## 8. 查看证据链

1. 打开报告详情。
2. 查看总分和各维度评分。
3. 查看风险点列表。
4. 查看证据链区域。
5. 查看简历写法建议。
6. 点击报告详情页的“打印 / 浏览器另存为 PDF”，在浏览器打印窗口的目标打印机中选择“另存为 PDF”。
7. 点击“生成分享链接”或“刷新分享链接”，复制只读分享链接。
8. 退出登录或使用无痕窗口打开分享链接，确认可以查看脱敏后的报告内容。

演示重点：

- 报告不是只给结论，还会展示依据。
- 证据链可以帮助用户判断哪些内容能写进简历，哪些需要降级表达。
- 报告详情页支持通过浏览器打印窗口另存为 PDF，当前版本不依赖后端 PDF 生成。
- 审计报告支持生成只读分享链接，公开页不暴露用户邮箱、用户 ID、AI Key、AI 调用日志、额度流水或原始项目源码内容。
- 当前为基础版分享能力，不包含访问统计和密码保护。
- 关闭分享后，原分享链接应提示失效或无权限。

## 9. AI 幻觉检测

1. 进入 AI 幻觉检测页面。
2. 选择项目，或直接粘贴 AI 对项目的评价。
3. 点击检测。
4. 查看可信度、客观性、风险点和更稳妥的改写建议。

可以粘贴的测试内容：

```text
这个项目非常完整，可以直接写进简历，面试基本没有问题。它体现了复杂系统设计能力，也可以包装成大型业务平台。
```

演示重点：

- 系统会识别过度鼓励和缺少证据的表达。
- 检测结果会提醒用户避免把不确定内容直接写入简历。

## 10. 模拟面试

1. 进入模拟面试页面。
2. 选择项目和面试模式。
3. 启动面试。
4. 回答第一轮问题。
5. 查看系统追问、评分和反馈。
6. 结束面试并查看总结。
7. 点击面试结果区的“打印 / 浏览器另存为 PDF”，在浏览器打印窗口的目标打印机中选择“另存为 PDF”，保存当前面试对话、评分、反馈和总结。

演示重点：

- 当前是规则版 V1。
- 更适合展示面试深挖思路，而不是把它包装成完整智能面试系统。
- 追问重点围绕项目真实性、技术细节和用户是否理解代码。
- 模拟面试复盘支持通过浏览器打印窗口另存为 PDF，当前版本不依赖后端 PDF 生成。

## 11. 查看额度

1. 进入额度页面。
2. 查看剩余额度。
3. 查看额度流水。

演示重点：

- 注册赠送额度。
- 报告生成消耗额度。
- 失败时返还额度。
- 当前没有接入支付，只是额度系统原型。

## 12. 管理员后台

1. 在 `.env` 中配置 `ADMIN_EMAILS`，重启 backend。
2. 使用对应邮箱的账号登录。
3. 确认侧边栏出现“管理员后台”入口。
4. 进入 `/admin`，查看用户数、项目数、报告数、项目问答数、分享报告数和今日新增统计。
5. 查看最近用户、最近项目、最近报告和最近问答表格。
6. 使用普通用户账号访问 `/admin`，确认页面显示“无权限访问管理员后台”，且不会展示数据。

演示重点：

- 管理员身份来自后端环境变量，不新增角色表或复杂 RBAC。
- `/api/admin/me` 用于前端判断入口是否展示，其他 `/api/admin/**` 数据接口会做管理员校验。
- 后台是只读看板，不提供删除用户、封号、改额度、导出数据等操作。
- 最近问答只展示问题摘要和 AI 是否参与，不返回完整证据 JSON。
